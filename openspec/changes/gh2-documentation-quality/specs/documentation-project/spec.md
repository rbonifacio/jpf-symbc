# Specification: Project Documentation

## Purpose

This capability defines the generation and maintenance of project-level documentation artifacts: `README.md` and `CLAUDE.md`. Both files MUST reflect the current state of the project after the Maven multi-module + Java 11 migration (gh1). The README serves external users and contributors; CLAUDE.md serves Claude Code (AI-assisted development).

Project documentation is generated by 2 sequential subagents: D1 produces `README.md`, D2 produces `CLAUDE.md`. The sequential ordering ensures that CLAUDE.md can reference README content if needed, though both files are largely independent.

### Documentation Files

```
README.md     <- Project introduction, setup, build, usage, architecture, testing, license
CLAUDE.md     <- Claude Code guidance: build commands, source layout, architecture, conventions
```

### Subagent Execution Model

| Subagent | Skill | Output | Dependency |
|----------|-------|--------|------------|
| D1 | `/sdd-doc-readme` | `README.md` | None (runs first) |
| D2 | `/sdd-doc-generate-claude-md` | `CLAUDE.md` | After D1 completes |

D1 and D2 execute sequentially. D2 runs after D1 to ensure consistency if CLAUDE.md references README content.

## Data Contracts

### Input

- **Build configuration**: Parent `pom.xml` + 5 module `pom.xml` files (source of truth for build commands, modules, dependencies)
- **Project structure**: Maven multi-module layout with 5 modules
- **Existing README.md**: Current content including any custom sections added by the project owner
- **Existing CLAUDE.md**: Current content with migration rules, build commands, source layout, architecture section, SDD Toolkit section
- **Test configuration**: `jpf-symbc-tests/pom.xml` (Surefire config, exclusions, JVM args)
- **jpf.properties**: Extension-level configuration (classpaths, peer packages, defaults)

### Output

- **Updated README.md**: Refreshed to reflect Maven build, Java 11, 5-module structure
- **Updated CLAUDE.md**: Refreshed to reflect current project state, build commands, architecture

### Side Effects

- `README.md` and `CLAUDE.md` are modified in place
- No source code changes
- No build configuration changes

## Invariants

- **INV-PRJ-01**: README.md installation and build commands SHALL be derived from the actual `pom.xml` configuration. Commands such as `mvn compile`, `mvn test`, `mvn package`, and `mvn install` MUST match the behavior defined in the parent and module POMs. The README SHALL NOT contain build commands that do not work with the current `pom.xml` structure (e.g., Ant commands like `ant build`, `ant test` are prohibited).

- **INV-PRJ-02**: CLAUDE.md build commands and configuration details SHALL be derived from the actual project configuration files (`pom.xml`, `jpf.properties`, `~/.jpf/site.properties`). Every build command listed in CLAUDE.md MUST be verifiable by executing it in the project root. Source layout paths MUST correspond to actual directories in the Maven multi-module structure.

- **INV-PRJ-03**: Neither README.md nor CLAUDE.md SHALL contain promotional, marketing, or aspirational language. Descriptions MUST be factual and technical. Phrases such as "powerful", "state-of-the-art", "world-class", "best-in-class" are prohibited unless they are part of an established project name or term of art.

- **INV-PRJ-04**: Custom sections in the existing README.md that were added by the project owner (sections not auto-generated by documentation tools) SHALL be preserved during updates. The update process SHALL identify custom sections, preserve their content, and integrate them into the updated README structure. If a custom section conflicts with a generated section, the custom section takes precedence and the generated content is merged or appended.

## Requirements

### Requirement: Update README.md (PRJ-01)

`README.md` SHALL be updated to reflect the Maven multi-module build system, Java 11 requirement, and current project structure. The README SHALL serve as the primary entry point for developers encountering the project.

The README SHALL include the following sections (order MAY vary):

1. **Project title and description** -- what jpf-symbc does (symbolic execution for Java bytecode via JPF)
2. **Prerequisites** -- Java 11 (OpenJDK 11+), Maven 3.6+, jpf-core built and installed to local Maven repository
3. **Installation / Setup** -- clone, build jpf-core, configure `~/.jpf/site.properties`, build jpf-symbc with `mvn install`
4. **Build commands** -- `mvn compile`, `mvn test`, `mvn package`, `mvn install`, `mvn clean`
5. **Project structure** -- 5 Maven modules with brief description of each
6. **Architecture overview** -- core packages, extension model (SymbolicInstructionFactory, SymbolicListener), solver backends
7. **Testing** -- how to run tests, test count, excluded tests, JUnit 4
8. **Configuration** -- `.jpf` file format, key properties (`symbolic.method`, `symbolic.dp`, `listener`)
9. **License** -- license information

#### Scenario: README Reflects Maven Build

- **WHEN** subagent D1 generates the updated README.md
- **THEN** all build commands use Maven (`mvn compile`, `mvn test`, `mvn package`, `mvn install`)
- **AND** no Ant commands (`ant build`, `ant test`, `ant compile`) appear anywhere in the file
- **AND** the Prerequisites section specifies Java 11 and Maven 3.6+
- **AND** the Installation section includes `mvn install` (not `ant build`)

#### Scenario: README Describes 5 Maven Modules

- **WHEN** the Project Structure section of README.md is inspected
- **THEN** all 5 Maven modules are listed: `jpf-symbc-annotations`, `jpf-symbc-main`, `jpf-symbc-classes`, `jpf-symbc-tests`, `jpf-symbc-examples`
- **AND** each module has a brief description of its purpose
- **AND** module dependencies are described (e.g., `jpf-symbc-main` depends on `jpf-symbc-annotations` and `jpf-core`)

#### Scenario: README Setup Instructions Are Functional

- **WHEN** a developer follows the Installation section step by step
- **THEN** the commands produce a successful build with `BUILD SUCCESS` output
- **AND** the `~/.jpf/site.properties` configuration matches the format required by JPF
- **AND** the jpf-core build step uses the official jpf-core repository (not the yannicnoller fork)

#### Scenario: Custom Sections Are Preserved

- **WHEN** the existing README.md contains custom sections (e.g., badges, acknowledgments, funding, special notes)
- **THEN** these sections are preserved in the updated README.md
- **AND** their content is not modified or truncated
- **AND** they are placed in a logical position within the updated structure

### Requirement: Update CLAUDE.md (PRJ-02)

`CLAUDE.md` SHALL be refreshed to reflect the current project state after the gh1 migration and gh2 documentation improvements. CLAUDE.md serves as guidance for Claude Code when working with the codebase.

CLAUDE.md SHALL include:

1. **Migration rules** -- the mandatory rules about direct modification, no adapters, backup before removal
2. **Project overview** -- what jpf-symbc is, Java 11 requirement
3. **Build commands** -- all Maven commands derived from `pom.xml` (`mvn compile`, `mvn test`, `mvn package`, `mvn install`, `mvn clean compile`)
4. **Test configuration** -- test exclusions, JUnit 4, Surefire configuration (forked, 1024MB, module system flags)
5. **Setup requirements** -- jpf-core build, `~/.jpf/site.properties`
6. **Source layout** -- Maven multi-module tree with module purposes and file counts
7. **Architecture** -- JPF extension model, core packages, constraint solver backends, configuration system
8. **SDD Toolkit section** -- preserved from current CLAUDE.md (infrastructure, workflow, skills, prerequisites)

#### Scenario: CLAUDE.md Build Commands Match pom.xml

- **WHEN** subagent D2 generates the updated CLAUDE.md
- **THEN** the Build Commands section lists `mvn compile`, `mvn test`, `mvn package`, `mvn install`, `mvn clean compile`
- **AND** test exclusions listed match the `<excludes>` in `jpf-symbc-tests/pom.xml`
- **AND** JVM arguments for tests match the `<argLine>` in `jpf-symbc-tests/pom.xml`
- **AND** no Ant commands appear in the file

#### Scenario: CLAUDE.md Source Layout Reflects Maven Structure

- **WHEN** the Source Layout section of CLAUDE.md is inspected
- **THEN** it shows the 5 Maven modules with their directory structure
- **AND** `jpf-symbc-classes` special handling is documented (3 compiler executions: default, java.base patch, java.desktop patch)
- **AND** build output paths use `target/` directories (not `build/`)
- **AND** file counts per module are accurate

#### Scenario: CLAUDE.md Preserves SDD Toolkit Section

- **WHEN** the existing CLAUDE.md contains an SDD Toolkit section (delimited by `<!-- SDD-SECTION-START -->` and `<!-- SDD-SECTION-END -->`)
- **THEN** the SDD Toolkit section is preserved in the updated CLAUDE.md
- **AND** its content is not modified, truncated, or reformatted
- **AND** it remains in its current position within the file

#### Scenario: CLAUDE.md Architecture Section Is Accurate

- **WHEN** the Architecture section of CLAUDE.md is inspected
- **THEN** it describes the JPF extension model (SymbolicInstructionFactory, SymbolicListener)
- **AND** it lists core packages with accurate file counts
- **AND** it describes the constraint solver backends (Z3, Choco, Coral, CVC3, etc.)
- **AND** it describes configuration via `.jpf` files with key properties
- **AND** all referenced class names and package paths exist in the current codebase

### Requirement: Sequential Subagent Execution (PRJ-03)

Project documentation generation SHALL use 2 sequential subagents (D1 then D2). D2 runs after D1 to ensure CLAUDE.md can reference the README structure if needed.

#### Scenario: Sequential Execution Order

- **WHEN** Phase 5 of the implementation plan is executed
- **THEN** subagent D1 (`/sdd-doc-readme`) executes first
- **AND** subagent D1 completes before subagent D2 is dispatched
- **AND** subagent D2 (`/sdd-doc-generate-claude-md`) executes second
- **AND** both subagents complete before Phase 6 (verification) begins

#### Scenario: Documentation Consistency

- **WHEN** both README.md and CLAUDE.md have been updated
- **THEN** build commands listed in README.md match those in CLAUDE.md
- **AND** module names and descriptions are consistent between the two files
- **AND** setup instructions do not contradict each other
- **AND** Java version requirement (11) is stated identically in both files
